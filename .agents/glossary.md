# Glossary

**Purpose:** Define the domain and code terms used across this repo so an agent can map a word to the concept and the doc that explains it.
**Read this when:** You hit an unfamiliar term in code, an input name, or another doc and need a grounded one-line meaning plus where to dig deeper.

Slugs link to sibling docs in `.agents/`. Definitions are grounded in this repo's source, not generic.

- **Actions Cache history** — Run history is persisted between CI runs via the GitHub Actions Cache (`src/history/actions-cache-storage.ts`), keyed per branch as a `HistoryFile` (`version: 1`, `branch`, `entries[]`). Enabled by the `history` input (default `true`), capped by `history-limit` (default 20). See [./history-analytics.md](./history-analytics.md).
- **annotation / annotation-level** — Inline failure markers on the PR diff, emitted as `annotation_level: 'failure' | 'warning' | 'notice'` (input `annotation-level`, default `failure`). Capped at `MAX_ANNOTATIONS`. See [./output.md](./output.md).
- **api-client** — HTTP client (`src/api/client.ts`) that POSTs an `ApiPayload` to `POST /api/v1/runs` with retry logic. Only runs when an `api-key` is present. See [./api-client.md](./api-client.md).
- **api-key** — Optional input. Absent (`!apiKey`) triggers **local-only mode**; the `api-url` and `api-key` inputs are currently reserved (SaaS dashboard pending). See [./inputs-reference.md](./inputs-reference.md), [./security.md](./security.md).
- **check run** — A GitHub Check Run created by `annotate-failures` to host inline annotations (`src/output/check-run.ts`); `conclusion` is `failure` when any test failed/errored, else `success`. Note the conclusion is advisory and never fails CI. See [./output.md](./output.md).
- **CTRF** — Common Test Report Format, a JSON test schema parsed natively in `src/parsers/ctrf.ts`. Its `tool.name` field feeds `toolName`/`framework` detection. See [./parsers.md](./parsers.md).
- **delta comparison** — `DeltaComparison` (`src/history/comparison.ts`): current run vs a baseline (typically the base branch), surfacing `testsAdded`, `testsRemoved`, `newlyFailing`, `newlyPassing`, plus pass-rate and duration deltas. See [./history-analytics.md](./history-analytics.md).
- **errored** — A `status` value distinct from `failed`: a test that erred (e.g. unhandled exception) rather than an assertion failure. Counted separately in `summary.errored`. See [./data-model.md](./data-model.md).
- **flaky (status flips)** — A test whose result alternates passed↔failed/errored across recent runs. `detectFlakyTests` counts `flipCount` over a 10-run window (skipped runs ignored); flagged when flips ≥ `flaky-threshold` (default 2). See [./history-analytics.md](./history-analytics.md).
- **floating v1 tag** — Consumers pin `testglance/action@v1`. The `release-v1` CI job force-retags `v1` onto the latest dist-bearing commit on `main`, so `@v1` always resolves to current built output. See [./build-and-release.md](./build-and-release.md).
- **FR5** — Product requirement that this Action is non-blocking: it never calls `core.setFailed()` and always exits 0. All errors surface via `core.warning()`. See [./known-issues.md](./known-issues.md), [./conventions.md](./conventions.md).
- **framework / toolName detection** — `detectFramework` (`src/utils/detect-framework.ts`) resolves the test framework: for CTRF it uses `tool.name`; for JUnit it path-matches (`vitest`, `jest`, `pytest`, `surefire`→`maven-surefire`). `toolName` rides on `ParsedTestRun`; `framework` rides on `MetaEnvelope`. See [./parsers.md](./parsers.md).
- **health score** — A 0–100 suite-health number blended over the last 30 days: 70% pass rate, 20% flakiness, 10% runtime trend (`src/output/format.ts`). Needs ≥5 runs; a fully green stable suite scores ~95. See [./output.md](./output.md).
- **highlights** — `Highlight[]` (`src/types.ts`): notable findings with `type` (`new_failures`, `fixed_tests`, `new_tests`, `duration_delta`, `known_flaky`, `health_score_delta`) and `severity` (`info`/`warning`/`critical`), rendered in summaries/comments. See [./output.md](./output.md).
- **JUnit XML** — The classic JUnit `<testsuites>/<testsuite>/<testcase>` XML format, parsed with `fast-xml-parser` in `src/parsers/junit.ts`. The default/auto-detected format. See [./parsers.md](./parsers.md).
- **local-only mode** — Active when no `api-key` is set (`const localOnly = !apiKey`): nothing is sent to the API (`send-results` forced false), but summaries, PR comments, annotations, and history still run. Suppresses the "API submission failed" banner. See [./api-client.md](./api-client.md), [./security.md](./security.md).
- **multi-job consolidation (tj-data marker)** — Each CI job is a separate Action invocation knowing only its own data. Per-job state is persisted as a hidden `<!-- tj-data:KEY base64 -->` blob inside the single PR comment; on each run all blobs are decoded and the whole comment is re-rendered, letting independent jobs share one consolidated table (`src/output/pr-comment.ts`). See [./output.md](./output.md).
- **ncc bundle** — `@vercel/ncc` compiles `src/index.ts` into a single `dist/index.js` referenced by `action.yml` (`main: 'dist/index.js'`). `dist/` is gitignored; only the `release-v1` CI job builds and commits it to `main`. See [./build-and-release.md](./build-and-release.md).
- **ParseError** — Custom `Error` subclass (`src/utils/errors.ts`) thrown by parsers on malformed input; handled non-blockingly via `core.warning()`, never `setFailed`. See [./parsers.md](./parsers.md), [./conventions.md](./conventions.md).
- **ParsedTestRun / ParsedSuite / ParsedTestCase** — The normalized parser contract (`src/types.ts`). `ParsedTestRun` = `{ summary, suites[], toolName? }`; `ParsedSuite` = `{ name, tests[], duration }`; `ParsedTestCase` = `{ name, suite, status, duration, errorMessage?, ... }`. Both parsers emit this. See [./data-model.md](./data-model.md).
- **perf regression (median)** — `detectPerfRegressions` (`src/history/perf-regression.ts`) flags a test when its current duration exceeds the **median** of its prior durations (≥3 history points) by more than `perf-threshold`% (default 200 = 3x). See [./history-analytics.md](./history-analytics.md).
- **recount rule** — Summary counts (`total/passed/failed/skipped/errored`) are recomputed from individual `<testcase>`/test elements, never trusting suite-level count attributes. See [./parsers.md](./parsers.md).
- **release-v1 job** — CI job in `.github/workflows/ci.yml` that rebuilds `dist/`, commits it to `main` as `chore: rebuild dist [skip ci]`, then force-retags `v1`. The only place `dist/` is committed. See [./build-and-release.md](./build-and-release.md).
- **self-test** — The CI `test` job runs the Action against the repo's own reports via `uses: ./` (which is why `dist/` is built on PRs). See [./testing.md](./testing.md), [./build-and-release.md](./build-and-release.md).
- **sparkline** — Compact unicode trend chart built from a numeric series with `buildSparkline` (`▁▂▃▄▅▆▇█`, `src/history/trends.ts`); rendered only with ≥5 entries. Used for pass-rate, duration, and perf trends. See [./output.md](./output.md).
- **status (passed/failed/skipped/errored)** — The four `ParsedTestCase.status` values; the canonical per-test outcome that drives every summary count and analytic. See [./data-model.md](./data-model.md).
- **suite vs test case** — A **suite** (`ParsedSuite`) is a named group with its own `duration` and a `tests[]` list of **test cases** (`ParsedTestCase`), each carrying its own `suite` back-reference. See [./data-model.md](./data-model.md).
- **tests-changed** — `TestsChangedReport` (`src/history/types.ts`): `newTests`, `removedTests`, `statusChanged` (with `previousStatus`) vs the previous run, plus `hasChanges`. Distinct from base-branch delta comparison. See [./history-analytics.md](./history-analytics.md).
- **trends** — `TrendIndicators` (`src/history/trends.ts`): pass-rate, duration, and test-count direction (`up`/`stable`/`down`) with deltas and sparklines, computed against the average of prior runs. See [./history-analytics.md](./history-analytics.md).
